按外部评审补两处硬缺口：可复现环境与部署口径

外部评审指出「项目当前无法启动」。我第一次核实得出「能跑」，这个核实是错的：
Git Bash 里的 python 装了依赖，Windows 终端里的 python（系统 3.12）没装。
用户按 README 走启动脚本时用的是后者，确实会撞 ModuleNotFoundError。
所以结论对、归因不全对：3.12 没被删，虚拟环境也不是失效而是从来没有。

启动脚本
- 探测 lightrag / fastapi / uvicorn / fastembed 四个关键包，缺了就打印可复制的
  venv + pip 两条命令并退出，不再抛裸 ModuleNotFoundError。
- 有 .venv 时优先用 .venv 的解释器。
- 刻意不做自动安装：往系统解释器装包会污染全局，且本机 pip 出现过静默挂起
  （零输出不退出），自动装卡住比报错更难排查。
- 提示里带上执行策略的绕法（默认策略会拦脚本，实测报 AuthorizationManager 检查失败）。
- 探测时临时关掉 ErrorActionPreference=Stop，否则 import 失败的 traceback
  会直接终止脚本（已实测踩到）。
- 保留 UTF-8 with BOM，否则 PowerShell 5.1 按 ANSI 读中文会引号配对错乱。
