# 错误码与排障对照

错误码设计原则：**同一类根因给同一个码**，不按"哪个模块抛的"编号。
所以 `E1061` 既可能是"引用了敏感列"，也可能是"跨租户访问"，
因为对上游来说都是"这条 SQL 不该被执行"。

码段划分：

| 段 | 范围 | 含义 |
|---|---|---|
| E10xx | 1001-1003 | 请求参数问题 |
| E10xx | 1010-1012 | 权限与租户 |
| E10xx | 1020-1032 | 语义层配置与校验 |
| E10xx | 1040-1042 | 限流与配额 |
| E10xx | 1050-1052 | 模型调用 |
| E10xx | 1060-1065 | SQL 解析与安全 |
| E10xx | 1070-1072 | 执行资源 |
| E10xx | 1080-1081 | 拒答（业务正常返回） |
| E10xx | 1090-1091 | 服务端状态 |

| E1002 | 400 | 问题过长 | question 超过 500 字符 | 截断或分段提问 |
| E1003 | 400 | 会话不存在 | session_id 未注册或已过期（24h） | 新建会话 |
| E1010 | 403 | 模型未授权 | API Key 无该模型权限 | 在控制台开通模型 |

| E1012 | 403 | 请求来源不在白名单 | Origin 不在 allowed_origins | 配置 allowed_origins |
| E1020 | 409 | 同名语义卡冲突 | tables.yml 与 metrics.yml 中 name 重复 | 改名或合并 |
| E1021 | 409 | 指标公式循环引用 | metric A 的 formula 引用 B，B 又引用 A | 拆解为原子指标 |
| E1030 | 422 | 语义层校验失败 | YAML 结构不满足 schema | 按错误提示修字段 |
| E1031 | 422 | 未知表名 | SQL 引用了 tables.yml 未声明的表 | 先补表卡 |

| E1062 | 403 | 禁止多语句 | SQL 中出现 ; 分隔的多条语句 | 只发一条 SELECT |
| E1063 | 403 | 禁止 DDL/DML | 出现 INSERT/UPDATE/DELETE/DROP 等 | 只允许 SELECT |
| E1064 | 403 | 禁止系统表 | 引用 sqlite_master / pragma 等 | 移除系统表访问 |
| E1065 | 403 | 禁止写文件函数 | 引用 load_extension / writefile 等 | 移除该函数 |
| E1070 | 408 | 查询超时 | 单条 SQL 超过 15s | 加 WHERE 缩小范围或预聚合 |
| E1071 | 507 | 结果集过大 | 返回行数超过 10,000 | 加 LIMIT |
| E1072 | 507 | 扫描行数超限 | EXPLAIN 估算扫描超过 500 万行 | 补索引或聚合下推 |
| E1080 | 200 | 证据不足拒答 | 检索与问题不匹配，判定器给出 NONE 锚点 | 换问法或补充文档 |
| E1081 | 200 | 超出文档范围 | 问题涉及产品未实现的能力 | 如实说明能力边界 |
| E1090 | 503 | 数据库只读快照不可用 | warehouse.sqlite 缺失或损坏 | 重新导出快照 |

## 三个容易误判的码

### E1080 看起来像错误，其实是正常返回

HTTP 状态是 200，`refused=true`。它表示"检索到的证据不足以回答"，
是产品的正确行为而不是故障。前端不要把它当异常弹红框，
排行榜统计里它也不进错误率分母——它进的是"拒答率"。

### E1052 上下文超长，先怀疑 top_k 而不是模型

出现 E1052 时，第一反应往往是"模型上下文不够"。实际上 32k 的窗口，
一张表卡约 400 token，6 张卡加问题也就 3k，真正把上下文撑爆的
是 few-shot 范例被整段拼进去。排查顺序：先看 `top_k`，
再看 fewshots 的 `tags` 是否命中过多。

### E1072 扫描行数超限，不是结果集超限

两者经常被混。结果集超限是 `E1071`（返回行数 > 10000），
扫描行数超限是 `E1072`（执行前估算要扫 500 万行以上）。
前者加 LIMIT 能解决，后者加 LIMIT 没用——因为过滤条件本身没走索引。
