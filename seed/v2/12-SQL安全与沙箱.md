# SQL 安全与执行沙箱

生成式 SQL 的风险不在"模型会不会写错"，而在"模型写对了一句你不想让它执行的语句"。
本项目把安全边界放在**解析层**而不是提示词层：提示词可以要求"只写 SELECT"，
但要求不是约束；`sqlglot` 解析出来的 AST 才是约束。

一条 SQL 的执行链路是固定的六步，任何一步失败都终止，不回退：

```
生成 → 解析(AST) → 18 条规则校验 → EXPLAIN 估算 → 只读连接执行 → 结果截断
         ↑失败 E1060      ↑失败 E1061~E1065      ↑超限 E1072      ↑超时 E1070
```

下面先讲 18 条规则，再讲沙箱本身，最后给几个真实的绕过尝试和它们为什么失败。

下面是逐条展开，重点写“为什么这么做”，因为规则本身一眼就能看懂，值钱的是当初为什么选这个做法而不是更简单的那个。

### G01 只允许单条语句

做法：解析后 AST 里语句数量必须为 1；出现分号分隔的多条语句直接拒绝。
理由：`SELECT 1; DROP TABLE t` 这类注入在 AST 层就是两条语句，正则永远抓不全。
拒绝码：`E1062`。

### G02 只允许 SELECT 及其子句

做法：语句类型白名单：Select / Union / With；其余一律拒绝。
理由：不靠关键词黑名单，靠 AST 节点类型判断，大小写、注释、换行都绕不过。
拒绝码：`E1063`。

### G03 表名必须在表卡白名单里

做法：AST 中每张表都要能在 tables.yml 找到同名条目。
理由：顺带解决“模型编了一张不存在的表”这类幻觉，报错信息比执行报错更好懂。
拒绝码：`E1031`。

### G04 列必须在表卡声明范围内

做法：每列要么在所属表的 columns 里，要么是聚合函数的别名。
理由：不允许 `SELECT *`：星号展开后可能带出未声明的敏感列。
拒绝码：`E1032`。

### G05 禁止访问系统表

做法：表名命中 sqlite_master / sqlite_sequence / pragma_* 即拒绝。
理由：系统表能读出全库结构，等价于泄露 schema。
拒绝码：`E1064`。

### G06 禁止 PRAGMA 语句

做法：pragma 节点单独判断，不走 SELECT 白名单。
理由：`PRAGMA writable_schema=1` 可以改 schema，是提权跳板。
拒绝码：`E1064`。

### G07 禁止 ATTACH / DETACH

做法：ATTACH 可以把任意路径挂成库。
理由：本地文件场景下 ATTACH 等于任意文件读。
拒绝码：`E1063`。

### G08 禁止危险函数

做法：黑名单含 load_extension / writefile / readfile / edit。
理由：SQLite 的扩展加载是原生代码执行，必须在解析层挡掉。
拒绝码：`E1065`。

### G09 禁止子查询访问未声明表

做法：子查询里的表名同样走 G03 检查。
理由：只查最外层表名是最常见的漏检。
拒绝码：`E1031`。

### G10 禁止 LIMIT 缺失的明细查询

做法：无聚合且无 LIMIT 的查询自动追加 LIMIT 1000。
理由：不是拒绝而是改写，因为用户意图通常是“看一眼”而非“全量导出”。
拒绝码：`E1071`。

### G11 扫描行数估算上限

做法：EXPLAIN QUERY PLAN 估算扫描行超过 500 万即拒绝。
理由：估算比实测便宜，先 EXPLAIN 再执行是硬性顺序。
拒绝码：`E1072`。

### G12 执行超时 15 秒

做法：sqlite3 progress_handler 每 10ms 检查累计耗时。
理由：超时中断而不是等它跑完，避免一个笛卡尔积拖垮整个进程。
拒绝码：`E1070`。

### G13 连接只读

做法：打开时 `mode=ro` + `PRAGMA query_only=1` 双保险。
理由：即使前 12 条全被绕过，物理上还是写不进去。
拒绝码：`E1090`。

### G14 敏感列脱敏

做法：user_phone / user_email / id_card 一律不进结果集。
理由：需要用到时只能取哈希或后四位，且要在 SQL 里显式写 substr。
拒绝码：`E1061`。

### G15 禁止跨租户表前缀

做法：表名出现 `tenant_` 前缀且不是当前租户即拒绝。
理由：多租户场景下的越权读取，靠表名前缀隔离。
拒绝码：`E1061`。

### G16 结果列数上限 50

做法：列数超过 50 的查询被截断并提示。
理由：列太多通常意味着模型在“把所有字段都选出来”而不是回答问题。
拒绝码：`E1071`。

### G17 保留字冲突校验

做法：别名与 SQL 保留字冲突时自动加引号。
理由：不拒绝，改写。中文别名不会冲突，英文别名会。

### G18 空结果不等于拒答

做法：执行成功但 0 行，如实返回空表并提示可能原因。
理由：这条是产品规则不是安全规则，但它决定了评测里“该拒答”和“该报空”的边界。


## 二、沙箱本身

数据库以只读方式打开，三层保护叠加，任何一层单独失效都不至于出事：

1. **URI 模式**：`file:warehouse.sqlite?mode=ro`，SQLite 在文件层拒绝写。
2. **会话级**：连上后立刻 `PRAGMA query_only = 1`，即使拿到写语句也执行不了。
3. **语句级**：G01~G08 在解析层就不放行。

超时用 `progress_handler` 实现，每 10ms 回调一次，累计超过 15 秒返回非零值中断查询。
这个机制的好处是不需要另起线程去 kill，坏处是回调本身的频率会影响长查询性能——
10ms 是在 2 万行/秒的扫描速度下调出来的，再密会明显掉速。

并发用信号量控制，默认 8 个。这个数字不是拍脑袋：压测时 8 并发下 p99 是 1.4s，
16 并发就劣化到 4.1s，因为 SQLite 的读锁在写快照重建时会短暂升级。
